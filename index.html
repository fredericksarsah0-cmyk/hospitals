🔐 PUIT24210078 Clinical Security Specification

This Hospital Management System implements a multi-layered cryptographic defense architecture designed to protect Electronic Health Records (EHR) and clinical access:

🧂 1. Per-User Cryptographic Salt (128-bit)

Every clinical staff account is assigned a unique, cryptographically random 128-bit hex string upon registration. Defense: Even if two doctors pick the same password, their resulting hashes are completely different. This completely eliminates precomputed Rainbow Table and dictionary attacks.

🌶 2. Confidential Application Pepper (HMAC Secret)

A server-side secret key known only to the running application environment and never stored in the database. Defense: In the event of an SQL dump or database exfiltration, attackers cannot test or crack password hashes without the server pepper.

⚙️ 3. Key Derivation: PBKDF2-HMAC-SHA512 (10,000 Iterations)

The password and pepper are combined and iteratively hashed with the user's salt 10,000 times, producing a 512-bit key. Defense: Computationally expensive to brute-force on modern GPU clusters.

📱 4. Two-Step Authentication (2FA) with OTP Code

Passing password verification only completes Step 1. A time-sensitive, single-use 6-digit numeric OTP is generated and dispatched to the clinician's registered contact channel (SMS & Pager simulation) with a 5-minute expiry timer. Access to the Hospital Management System remains strictly locked until the valid OTP code is submitted.
